Problem Statement

The Skill Gap in Financial AI Agents

Modern LLM-powered agents rely on tool-calling to answer complex financial queries. However, hand-crafting agent skills is expensive, brittle across model configurations, and does not scale. FinSkillsTracer addresses this gap by automatically mining skills from execution traces.

Core Challenges Addressed

Tool Proliferation

17 tool types across 14 LLM configs create combinatorial explosion — agents waste calls on redundant exploration instead of exploiting known patterns.

Configuration Fragility

Skills hand-tuned for one model break on others. Our cross-model consensus mechanism validates skills that generalize across all 14 configurations.

Parameter Wiring

Tool outputs must feed into subsequent tool inputs. Manual wiring is error-prone; automated data-flow detection achieves 76.4% parameter match rates.

Solution Architecture

Three-Phase Optimization Pipeline

The pipeline processes raw traces through three stages: Mine (discover candidate skills from traces), Evaluate (measure real utility with error mining and benchmarks), and Optimize (evolve skills through mutation, crossover, and data-flow parameterization).

Phase 1

Skill Mining — Five Complementary Strategies

Five distinct mining strategies are applied to the same 7,000 traces. Each uncovers a different class of reusable patterns. Strategies A and E dominate on coverage; B-D provide semantic and structural signals for downstream evolution.

A  FSP — Frequent Sub-sequence Pattern Mining

Sliding-window enumeration of all tool-name subsequences (length 2-5) across all traces. Patterns appearing ≥ min_support (5) traces are promoted to candidate skills. Result: 177 skills, 96.04% coverage, 24.9% consensus rate.

Example: [WebSearch, WebSearch, WebSearch] → support 8,991 instances

B  Semantic — K-Means Clustering + LLM Description

Tool sequences are embedded as feature vectors and clustered via k-means (k=10). Each cluster centroid triggers an LLM-generated skill name and natural-language description. Result: 10 semantically coherent skill clusters.

Example: "Corporate Expansion Tracking" — semantic cluster of single-WebSearch patterns

C  Hierarchical — Recursive Boundary Detection (P3.1)

Three signal types detect sub-goal boundaries in traces: (1) tool-category transitions, (2) duration spikes (>3× median neighbor), (3) I/O dependency chain breaks. Recursively segments traces into a 3-level tree. Result: 87 skills, 5 categories.

Categories: financial_direct (27), web_search (47), financial_mcp (14), web_fetch (2), file_ops (2)

D  Trace2Skill — Direct Extraction from Annotated Segments

Annotated trace segments (where human or LLM judges marked "skill boundaries") are extracted directly as candidate skills. High precision, low recall. Result: 21 curated skills, 95.24% uniqueness.

E  SkillClaw — Merge + Evolutionary Optimization (P3.3)

Starts by merging identical tool-name sequences (canonical name normalization), then applies evolutionary operators over 5 rounds. Result: 181 evolved skills, 96.04% coverage, 98.83% uniqueness.

Evolution: 295 raw → 206 V1 merge → 181 evolved (38.6% compression)
Phase 2

Real-Utility Evaluation

Phase 1 confidence scores were placeholders (1.0 for all golden-only skills). Phase 2 introduces real error-based confidence from all 7,000 traces, plus agent-vs-agent benchmarking and LLM-based skill quality assessment.

P2.1 — Error Pattern Mining (7,000 Traces Analyzed)

We separate tool-level errors (API failures, timeouts, invalid parameters) from answer-level errors (incorrect financial data, hallucinated metrics). This enables real per-skill confidence scores — a skill may execute correctly (tool confidence = 1.0) but produce wrong answers (answer confidence = 0.39).

Key Insights

  • WebFetch dominates errors (75.4% of all tool errors) — unreliable for financial data extraction; consider replacement with Daloopa API calls.
  • MCP namespace tools have 429× higher error rate than direct Daloopa API — namespace translation overhead causes parameter loss.
  • 5.15% overall tool error rate across 7,000 traces — 979 traces affected by at least one tool failure.
  • Answer error rate is 29.0% (2,028 / 7,000 traces) — even tool-correct traces can produce bad financial data.
  • Per-skill confidence replaces global placeholder: "Corporate Expansion Tracking" has tool_conf=1.0 but answer_conf=0.442.

P2.3 — LLM Skill Quality Judge

Each skill is scored by an LLM judge on three dimensions (1-10 scale). Skills below threshold are flagged for evolution or deprecation.

  • Usefulness: How much does this skill reduce agent workload?
  • Completeness: Are all necessary sub-steps included?
  • Generality: Does the skill apply across query types?

3-Signal Boundary Detection

1. Category Transitions

When a tool category changes (e.g., web_search → financial_direct), a sub-goal boundary is likely.

2. Duration Spikes

When a tool call takes >3× the median duration of its neighbors, it completes a sub-goal.

3. I/O Dependency Chains

Tools sharing output→input data flow belong to the same sub-goal. Break when no flow exists.

Cross-Instance Voting & Parameter Type Inference

Instead of extracting the first template, we collect ALL instances of a skill sequence and vote on parameter types across every occurrence. This avoids overfitting to a single trace.

Implementation: Recursive JSON Parsing

Daloopa API outputs are nested JSON strings wrapped in {"type":"text","text":"{...}"} envelopes. Our parser recursively unwraps these to extract structured keys (e.g., company_id, series_ids) for data-flow matching.

// Step 1 output (raw) {"type":"text","text":"{\"company_id\":320193,\"ticker\":\"AAPL\"}"} // Parsed keys company_id = 320193, ticker = "AAPL" // Step 2 input key-matched input: { company_id: 320193 } ← derived from Step 1

Multi-Round Evolutionary Algorithm

5 rounds of evolution with 5 mutation operators + crossover, guided by a multi-objective fitness function.

merge_namespace collapse_loop add_tool delete_tool replace_tool crossover elitism

Fitness Function

fitness = 0.3 × coverage + 0.3 × consensus + 0.2 × support_norm + 0.2 × (1 − uniqueness_penalty)
  • Tournament selection: k=3, pick best fitness from random triple
  • Elitism: preserve top 20 skills per generation
  • Convergence: stop when fitness change < 0.001 between rounds
  • Backward-compatible: V1 SkillClaw kept for Phase 1/2 pipelines
